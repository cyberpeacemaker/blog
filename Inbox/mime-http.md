**MIME** 的全名是 **Multipurpose Internet Mail Extensions**（中文通常翻譯為：**多用途網際網路郵件擴展協定**）。

雖然它的名字裡有「Mail（郵件）」，但它現在早已不只用在郵件中，而是**整個網際網路（包含網頁、下載、網路安全）在辨識檔案類型時的「世界通用標準語言」**。

## 1. 為什麼叫這個名字？（由來小故事）

在 1990 年代初，網際網路剛剛起步，那時的電子郵件（Email）非常陽春，**只支援傳送「純英文純文字」**（US-ASCII 編碼）。

如果你想在郵件裡夾帶一張圖片、一首歌或是一個 PDF 檔，當時的技術是完全行不通的，因為系統會把它們當成一堆亂碼。

為了解決這個痛點，工程師們在 1992 年發明了 **MIME** 協定：

- 它規定了一套機制，可以把圖片、影片、壓縮檔等「非文字檔案」轉換成文字編碼放進郵件裡。
    
- 同時，它還會在郵件標頭加上一項標記，告訴收件方的郵件軟體：「**這是一張 JPEG 圖片，請幫我把它還原顯示出來！**」
    

這個標記，就是我們今天看到的 **MIME 類型（MIME Type）**。

## 2. 後來它怎麼成了網頁的霸主？

MIME 在郵件上大獲成功後，網際網路（HTTP 協定）也遇到了同樣的問題：當瀏覽器向伺服器請求一個網頁時，伺服器要怎麼告訴瀏覽器「這是一個網頁（HTML）」、「這是一張圖片（PNG）」還是一首「音樂（MP3）」？

網頁開發者們不想重新發明輪子，於是直接把 MIME 這一套檔案分類標準搬到了網頁上。

現在，每當你點擊一個網址，伺服器回傳的 HTTP Header 裡都會帶有這個欄位：

HTTP

```
Content-Type: text/html             <-- 告訴瀏覽器：這是網頁，請渲染它
Content-Type: image/png             <-- 告訴瀏覽器：這是圖片，請顯示它
Content-Type: application/zip       <-- 告訴瀏覽器：這是壓縮檔，請下載它
```

## 3. MIME 類型的格式長怎樣？

MIME 採用非常直覺的「雙層結構」分類法，格式為：**`主要類型 (Type) / 子類型 (Subtype)`**

以下是常見的幾種類型：

|**主要類型 (Type)**|**常見子類型 (Subtype)**|**說明**|
|---|---|---|
|**`text`** (純文字)|`text/html`, `text/css`, `text/plain`|瀏覽器可以直接閱讀的文字|
|**`image`** (圖片)|`image/jpeg`, `image/png`, `image/gif`|各種圖檔|
|**`audio`** / **`video`**|`audio/mpeg`, `video/mp4`|影音串流檔|
|**`application`** (應用程式/二進位)|`application/pdf`, `application/zip`, `application/x-dosexec`|需要特定軟體處理，或直接下載的二進位檔案（如 PDF, ZIP, EXE）|

> 💡 **資安冷知識：**
> 
> 在我們前面聊到的 Zeek 工具中，當它識別出一個 Windows 執行檔（`.exe`）時，它記錄的 `mime_type` 就是 **`application/x-dosexec`**（意思是：一個 DOS 時代延續至今的 Windows 可執行二進位檔）。

## 總結

**MIME** 就是網際網路上各個設備（瀏覽器、郵件軟體、Zeek 監控器）在溝通時，用來**宣告「這個檔案是什麼鬼東西」的官方標準身分證**。
