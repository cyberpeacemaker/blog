哈哈，很多人都是這樣！GitLens 因為功能太強大、選單太多，剛裝的時候很容易迷路，最後就把它當成裝飾品放著養蚊子。

既然你已經裝了，我們先用**最簡單、最有感**的 3 個招式把它點亮，接著再推薦你幾款現代開發者幾乎人手一套的「神級標配」外掛！

## 🚀 既然裝了，就從這 3 招開始玩 GitLens！

不用去記複雜的快捷鍵，你在寫程式時順手試試這三功能：

### 1. 游標停一下，看「淡淡的灰字」與懸浮視窗

- **怎麼用：** 把你的滑鼠游標隨便點在任何一行程式碼上。
    
- **看哪裡：** 該行的最右邊會出現一串淡淡的灰色文字（寫著誰在幾個月前改的）。此時**把滑鼠移到那串灰字上**，會彈出一個精美的小視窗。
    
- **威力所在：** 視窗裡不只有 Commit 訊息，還可以直接點擊 **「Changes」**（看這次改動）、**「Commit Hash」**（複製 ID），甚至是連動 GitHub 的 **「Pull Request」**。
    

### 2. 右上角「小人頭」：一鍵開啟全檔案 Blame

- **怎麼用：** 打開任意檔案，看著 VS Code 編輯器**右上角**那一排小圖示。你會發現裝了 GitLens 後多了幾個圖標，其中一個是 **「Toggle File Blame」**（通常是一個小人頭或是像書卷的圖示）。
    
- **威力所在：** 點下去！整份檔案左側就會刷出一整片精美的主題顏色區塊，按時間遠近排序，誰寫了哪幾行一目了然。再點一次就關閉，非常方便。
    

### 3. 左側專屬側邊欄：追蹤「行歷史 (Line History)」

- **怎麼用：** 點擊 VS Code 最左側活動列的 **GitLens 圖示**（一個像分支的標誌），會打開一堆面板。
    
- **威力所在：** 找到 **「LINE HISTORY」** 這個面板。當你在程式碼點選某一行時，這個面板會「即時連動」，單獨列出**這特定一行程式碼**在過去幾年內被改動的所有歷史。這在抓特定 Bug 時是開掛般的速度。
