「工作交付物」最標準、最常用的英文是 **Deliverables**（或 **Work Deliverables**）。

根據具體的職場情境與產業特性，還有幾種非常地道的說法：

### 1. Deliverables（最常用、最推薦）

專案管理（PMP）與商業職場中最標準的用語。無論是報告、設計稿、軟體模組還是分析圖表，只要是約定好要交出來的成果，都可以稱為 **Deliverables**（通常用複數）。

- **例句：** We need to submit all final **deliverables** by Friday.
    
    （我們需要在週五前提交所有最終交付物。）
    
- **例句：** What are the key **deliverables** for this project?
    
    （這個專案的主要交付物有哪些？）
    

### 2. Work Products（較正式、偏合約與工程規範）

常用於法律合約、顧問業或特定工程規範（如 CMMI）中，強調「工作過程中所製造出來的成品或產物」。

- **例句：** All **work products** created during the contract period belong to the client.
    
    （合約期間產出的所有工作交付物均歸客戶所有。）
    

### 3. Artifacts（敏捷開發 / 軟體工程專用）

在敏捷開發（Agile / Scrum）或 UX 設計領域，常把產出的文件、模型、程式碼增量等稱為 **Artifacts**（產出物/物件）。

- **例句：** The design team will share the latest UX **artifacts** with the developers.
    
    （設計團隊將會與開發人員共享最新的 UX 交付物件。）
    

### 4. Outputs（廣義的「產出」）

如果不想顯得太像專案管理術語，只是指日常工作「產出的東西」，用 **Outputs** 最自然白話。

- **例句：** Our main **output** this week will be the market research report.
    
    （我們本週的主要工作產出是市場調查報告。）
    

### 5. Outcomes（強調「成果/效益」）

若你的交付物不只是單純的一份文件，而是強調「交付後帶來的實質效益或成果」，可以用 **Outcomes**。

- **例句：** Management is more interested in business **outcomes** than just daily tasks.
    
    （管理層比起日常任務，更看重商業成果。）
    

### 快速選用指南

| **適用情境**                  | **建議使用的英文**       |
| ------------------------- | ----------------- |
| **一般專案 / 跨部門溝通 / 對客戶**    | **Deliverables**  |
| **合約簽署 / 智慧財產權歸屬 / 工程規範** | **Work Products** |
| **軟體開發 / 敏捷團隊 / 設計師**     | **Artifacts**     |
| **日常工作回報 / 口語溝通**         | **Outputs**       |
