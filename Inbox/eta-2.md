### 3 個進階 ETA 威脅狩獵場景

#### 範例 6：利用合法雲端服務（SaaS）作為 C2 通道 (Living off the Cloud)

- **獵捕假設：** 攻擊者不再自己架設可疑的 C2 伺服器，而是直接利用 Telegram, Discord, Slack, 或 Microsoft Graph API 作為控制通道。因為目標網域（SNI）完全合法（例如 `api.telegram.org`），傳統的情資阻擋與網域商譽檢測（Domain Reputation）完全失效。
    
- **ETA 偵測特徵：**
    
    - **連線基線比對（Baseline Anomaly）：** 正常員工使用 Telegram 的流量特徵（傳送圖片、語音、長訊息）在時間和大小上非常隨機。而惡意程式呼叫 API（如定期輪詢 `/getUpdates`）會呈現極小的 JSON 請求與回應，**高度規律、封包大小極度固定且集中於特定端點**。
        
    - **TLS 指紋異常（JA3）：** 雖然目的地是 Telegram，但發起請求的程式並非官方客戶端，其 JA3 指紋會暴露出它是 Python (Requests/Urllib)、Go 或 PowerShell 寫成的惡意腳本，這與一般使用者的瀏覽器或 App 截然不同。
        

#### 範例 7：隱蔽的 RDP-over-HTTPS 隧道 (Chisel / Ngrok)

- **獵捕假設：** 攻擊者在內網部署了像 Chisel 或 Ngrok 這樣的隧道工具，將內網的遠端桌面（RDP）或 VNC 流量封裝在 HTTPS (TLS) 隧道中，繞過防火牆傳出外網，進行遠端操控。
    
- **ETA 偵測特徵：**
    
    - **SPLT 的「雙向對稱性與互動性」：** 遠端桌面連線是「高度互動式」的。當操作者在畫面上動滑鼠或敲鍵盤，會立即產生極高頻率的微小加密封包（上行）；而螢幕畫面更新則會回傳連續的較大加密封包（下行）。這種**上行微小、下行連續且同步發生**的加密封包特徵，與一般網頁瀏覽（讀完就靜止）或單向檔案傳輸有著完全不同的特徵譜。
        

#### 範例 8：加密的加密貨幣挖礦流量 (Stratum over TLS)

- **獵捕假設：** 內網主機被植入挖礦程式（Miner），並透過加密的 Stratum 協定（通常走 TLS Port 443 或 5555）連接到外部礦池。
    
- **ETA 偵測特徵：**
    
    - **心跳與酬載特徵：** 挖礦連線會定期發送「工作請求」（Getwork）與「提交雜湊值」（Submit Share）。其 SPLT 表現為極度精準的週期性連線，且每次的封包長度幾乎一模一樣（例如始終在 150 到 300 位元組之間）。
        
    - **自簽名與特殊 CA：** 許多礦池使用免費或自簽名的憑證，其憑證的 Subject 經常包含 `mine`、`pool`、`xmr` 等敏感關鍵字。
        

### 核心數學與統計學指標：威脅獵人如何「盲測」流量？

當我們完全無法看見加密內容時，ETA 的底層分析引擎會利用**統計學特徵**來做規則判定或訓練機器學習模型。以下是威脅獵人最常用的兩個數學分析維度：

#### 1. 資訊熵 (Shannon Entropy)

資訊熵用來衡量資料的混亂程度（隨機性）。公式如下：

$$H(X) = -\sum_{i=1}^{n} P(x_i) \log_2 P(x_i)$$

其中 $P(x_i)$ 是某個位元組（Byte）出現的機率。

- **正常明文 / 程式碼：** 熵值較低（約 3 到 5），因為特定英文字母、空白、HTML 標籤出現頻率很高。
    
- **加密流量或壓縮檔：** 熵值極高，通常接近最大值 8（代表每個位元組出現的機率高度隨機且平均）。
    
- **狩獵應用：** 如果我們在未經定義的非標準通訊埠（非 443）看到熵值逼近 8 的持續流量，且連 TLS 握手都沒有，那幾乎可以判定是經過強加密或強混淆的自建 C2 協定。
    

#### 2. 封包間隔時間 (Inter-Arrival Time, IAT)

透過計算相鄰兩個封包到達時間的差值：

$$\Delta t = t_i - t_{i-1}$$

- **人類行為：** $IAT$ 的標準差非常高，呈現泊松分佈（Poisson Distribution），因為人類敲鍵盤、點網頁的速度很不固定。
    
- **機器行為（C2 心跳 / 挖礦）：** $IAT$ 的標準差趨近於 0，時間間隔高度集中（例如總是精準的 5.00 秒 $\pm$ 0.05 秒）。
    

### 實戰：Zeek 日誌中的 ETA 獵捕線索

在實際狩獵中，我們常利用開源網路分析工具 **Zeek**。以下是一個典型的 Zeek `ssl.log` 加密分析日誌，我們來看看威脅獵人是如何從中揪出鬼魅的：

JSON

```
{
  "ts": 1781512345.67,
  "uid": "CHg68619Hi8L6df87a",
  "id.orig_h": "192.168.1.105",       // 內部受害主機 (資料庫伺服器)
  "id.resp_h": "104.244.42.1",         // 外部目的地
  "id.resp_p": 443,
  "version": "TLSv1.3",
  "cipher": "TLS_AES_256_GCM_SHA384",
  "server_name": "api.telegram.org",  // 雖然 SNI 看起來完全合法
  "ja3": "98146aa27ed76e1a0b5b2f2939e6a0d2", // 但此 JA3 指紋與 Telegram App 不符
  "established": true,
  "subject": "CN=api.telegram.org",
  "issuer": "CN=DigiCert TLS Hybrid ECC SHA256, O=DigiCert Inc, C=US"
}
```

**獵人的分析邏輯：**

1. 雖然 `server_name` 與 `subject` 看起來是完全合法的 Telegram，憑證發行商也是合法的 DigiCert。
    
2. 但是發起連線的 `id.orig_h`（192.168.1.105）在企業內網中是一台**後台資料庫伺服器**。為什麼資料庫會需要主動連線到 Telegram 伺服器？
    
3. 進一步比對 `ja3` 指紋，發現這個指紋對應的是 **"Python-urllib"** 或 **"Go-http-client"**，而非 Telegram 官方客戶端或標準瀏覽器。
    
4. **結論：** 這是一起高度可疑的「資料庫伺服器遭植入惡意腳本，正透過 Telegram API 進行 C2 指令控制」事件。
