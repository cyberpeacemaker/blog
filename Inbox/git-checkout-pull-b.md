太懂了！這真的是每個工程師每天開工的「儀式感」。你記得的完全沒錯，多人協作時開工第一件事，就是**把遠端最新的程式碼拉下來**，並**開一個自己的小分身（分支）來寫程式**。

以下為你整理一套最標準、最不容易撞車（衝突）的開工指令流程：

## 🛠️ 多人開發：每日標準開工 3 步驟

### 1. 切換到主分支

先把你的工作環境切回團隊的主要分支（通常叫 `main` 或 `master`，有些團隊叫 `dev`）：

Bash

```
git checkout main
```

> 💡 **小知識**：現代 Git 也很推薦用 `git switch main`，語意更直覺！

### 2. 拉取最新程式碼

因為其他人昨天或剛才可能更新了程式碼，必須把最新的內容同步到你電腦：

Bash

```
git pull
```

### 3. 開啟你今天要做的工作分支（極度重要！）

**千萬不要直接在 `main` 分支上寫程式碼！** 踩到別人的腳掌會很痛。請開一個屬於你今天任務的新分支：

Bash

```
git checkout -b feature/add-login-page
```

> 💡 這個指令的意思是：「新增一個叫 `feature/add-login-page` 的分支，並立刻切換過去」。

## 📋 懶人包：開工指令一覽

下次打開專案，照著這三行依序打就對了：

Bash

```
git checkout main
git pull
git checkout -b 你的功能名稱
```

> **小提醒**：如果你的專案有用到套件管理工具（例如 Node.js 的 `npm`），拉完最新的程式碼後，偶爾也可以順手打個 `npm install`，確保夥伴新增的第三方套件也有安裝到你的電腦上。

你想知道寫完程式後，要怎麼把程式碼「推上去（Push）」並發 PR 給同事審核的指令嗎？還是你們團隊有特別用其他的 Git 流程呢？
