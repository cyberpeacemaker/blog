簡單來說，**RAG（Retrieval-Augmented Generation，檢索增強生成）** 就是讓大型語言模型（LLM）從「**閉卷考試**」變成「**開卷考試**」的一套技術架構。

傳統的 LLM 只能依靠模型參數裡的記憶來回答問題（如同憑印象作答），容易出現記憶模糊（生成幻覺）或無法掌握最新與私有資訊的問題。RAG 的做法是在模型回答前，先去「外部知識庫」精準搜尋相關文件，再將這些資料作為參考依據（Context）提供給 LLM 來生成答案。

## 為什麼需要 RAG？（解決 LLM 的 3 大痛點）

- **抑制模型「胡說八道」（降低幻覺）：**
    
    LLM 有時會非常自信地給出錯誤答案。RAG 要求模型「看書作答」，把生成的內容錨定（Grounding）在權威資料上，大幅提升可信度。
    
- **無縫連結「新知識」與「私有資料」：**
    
    模型自身的訓練資料有時效截止點（Knowledge Cutoff），且不包含企業內部的機密或專業規格。透過 RAG，無需重訓模型就能即時補充新資訊。
    
- **靈活且低成本（比 Fine-tuning 更省錢）：**
    
    重新訓練或微調（Fine-tune）幾十億參數的模型非常昂貴且耗時；而 RAG 只需要更新外部資料庫的內容，就能隨時完成知識替換。
    

## RAG 的運作流程：三大步驟

一個標準的 RAG 系統包含以下三個核心階段：

```
[原始文件] ➔ (切塊/向量化) ➔ [向量資料庫] 
                               │ (搜尋相關片段)
[使用者提問] ───────────────➔ [檢索器 Retrieval] ➔ [Prompt 組合] ➔ [LLM 生成答案]
```

1. **索引階段（Indexing）：**
    
    - 將大量文件（如 PDF、網頁、規章）切成適當大小的文字區塊（Chunks）。
        
    - 利用 Embedding 模型將文字轉化成語意向量，存入向量資料庫（Vector Database）。
        
2. **檢索階段（Retrieval）：**
    
    - 當使用者提出問題時，系統將問題同樣轉為向量。
        
    - 在向量資料庫中搜尋語意最相關的 Top-N 個文本區塊。
        
3. **生成階段（Generation）：**
    
    - 系統將「使用者問題」與「檢索到的參考文本」合體組成提示詞（Prompt）。
        
    - 送交 LLM，讓模型根據資料整理出精準回答。
        

## RAG 的技術演進

|**發展階段**|**特色與重點**|
|---|---|
|**Naive RAG（基礎版）**|簡單的「檢索 $\rightarrow$ 拼接 $\rightarrow$ 生成」流程，容易受到雜訊或無效切塊干擾。|
|**Advanced RAG（進階版）**|引入 **Query 改寫**、**混合檢索（Hybrid Search，關鍵字+向量）** 與 **重排序（Reranking）**，精確篩選高品質資料。|
|**Agentic RAG（代理人版）**|（如我們前面探討的資安架構）將 RAG 封裝為 Agent 可使用的工具。LLM 能**自主判斷**何時該檢索、去哪裡檢索，甚至在結果不佳時自動修正關鍵字重新檢索。|

> **一句話總結：**
> 
> RAG 是將「外掛大腦（知識庫）」與「推理引擎（LLM）」相結合的最佳橋樑。
