我完全懂你的痛點！GitHub 預設點進去 Commit 就會把那次提交的「所有改動檔案」鋪天蓋地列出來，如果那次改動了幾十個檔案，只想看 `README.md` 就會找到眼花。

要在 GitHub 上獲得像 VS Code 那樣只專注在單一檔案的 Diff（差異對照）體驗，點進 Commit 後你可以使用以下**兩種最有效率的方法**：

### 方法一：使用左側檔案樹的「篩選功能」（最像 VS Code）

當你在 `image_80f1c4.png` 的畫面上點擊任何一個 Commit（例如 `docs: soften attribution wording`）進入後：

1. **找到左側的檔案樹（File Tree）：** 頁面的左側會有一欄列出這次 Commit 修改的所有檔案目錄。
    
2. **使用過濾器（Filter）：** 在檔案樹的最上方，有一個 **「Filter files」** 的搜尋輸入框。
    
3. **輸入檔名：** 直接輸入 `README.md`。此時左側的樹狀圖會被過濾到**只剩下這一個檔案**。
    
4. **點擊查看：** 點擊它，右側的畫面就會立刻跳到該檔案的改動。雖然下方可能還看得到其他檔案，但左側側邊欄已經被你淨空，你可以像在 VS Code 一樣快速切換與專注。
    

### 方法二：善用「隱藏已檢視」或「折疊」功能

如果該次 Commit 的其他檔案真的很礙眼，在進入 Commit 頁面後：

- **折疊不要看的檔案：** 滾動到其他不相關的檔案時，點擊該檔案右上角的 **「Chevron 箭頭 (折疊)」** 圖示，或是勾選 **「Viewed (已檢視)」** 方塊，該檔案的詳細程式碼就會立刻縮起來，讓整個頁面只留下 `README.md` 的內容。
    

### 補充祕技：想看「逐行」的歷史演變？試試 Blame！

如果你不是想看某個 Commit 的 Diff，而是想看 `README.md` 裡面**每一行程式碼「各自是在哪一個 Commit 被誰改的」**：

1. 回到 `README.md` 的檔案瀏覽頁面。
    
2. 點擊右上角的 **「Blame」**（或者是條形圖圖示的 Git Blame）。
    
3. 畫面就會把整份檔案攤開，左側會清清楚楚顯示每一行程式碼的最後修改者、Commit 訊息與時間，這也是另一個在 VS Code 中非常常用的強大功能！

哈哈，對吧！`git blame` 絕對是開發者的「時空旅行/考古神手」。雖然它的名字叫 "Blame"（怪罪/找戰犯），聽起來火藥味很重，但在實際開發中，它更像是一個**故事書**，告訴你每一行程式碼背後經歷了什麼。

下面為你詳細拆解 `git blame` 的核心威力，以及如何在 VS Code 裡玩轉它！

## 💡 什麼是 Git Blame？它能解決什麼痛點？

簡單來說，`git blame` 的功能就是：**把一份檔案拆開，在每一行程式碼旁邊，標註是「誰」在「什麼時候」因為「哪一個 Commit」寫下這行程式的。**

> **建功還是抓戰犯？常見的三大使用場景：**

1. **程式碼看不懂時：** 看到一行長得很奇葩的程式碼，快要吐血時，用 Blame 一查，發現是三年前的自己寫的（默）。
    
2. **尋找脈絡（Context）：** 想知道為什麼這裡要多加一個 `if` 判斷？透過 Blame 找到 Commit ID，點進去看當時的 Commit Message 或 Pull Request，就能明白當時是為了解決什麼特殊的 Bug。
    
3. **問對人：** 發現某段邏輯需要修改，但怕改壞，直接用 Blame 看最近是誰動的，直接過去拍他肩膀討論。
    

## 🛠️ 在 VS Code 裡使用 Blame 的三種姿勢

VS Code 本身有一些基本功能，但要達到「極致流暢」的 Blame 體驗，通常會搭配強大的外掛。

### 1. 神級外掛：GitLens（最推薦，工程師標配）

如果你在 VS Code 裡只能裝一個 Git 外掛，那絕對是 **GitLens**。裝上它之後，你會得到以下超能力：

- **行內隱形提示 (Current Line Blame)：** 當你的游標停在任何一行程式碼上，那行程式碼的右邊就會出現淡淡的灰色文字，寫著：_「You, 2 days ago • feat: add login...」_。完全不用點任何按鈕，看程式碼的同時就在看歷史！
    
- **懸浮視窗 (Hover)：** 游標移到那行灰色字上，會跳出一個精美的視窗，顯示完整的 Commit 訊息、更改日期、甚至可以直接點擊連結跳到 GitHub 看那次的 PR。
    
- **檔案 Blame 側邊欄：** 點擊編輯器右上角的「小人頭」或「檔案歷史」圖示，左側會整齊排開這份檔案的所有修改者，還會用顏色深淺幫你區分時間遠近（越有創意的程式碼顏色越亮）。
    

### 2. 輕量級選擇：Git Blame 外掛

如果你覺得 GitLens 太多功能、太吃電腦記憶體，可以在擴充功能（Extensions）搜尋並安裝 **"Git Blame"**。

- 它非常純粹，只會在 VS Code **最下方的狀態列（Status Bar）** 顯示你目前游標所在行的修改資訊。
    
- 乾淨、不打擾、需要時看一眼下方就好。
    

### 3. VS Code 內建：時間軸功能 (Timeline)

如果你堅持不裝任何外掛，VS Code 其實內建了一個神祕的角落：

1. 打開左側的檔案瀏覽器（Explorer）。
    
2. 在最下方找到一個叫 **「TIMELINE」** 的面板（如果沒看到，在空白處點右鍵勾選 Timeline）。
    
3. 只要你點擊任何檔案，這裡就會按時間順序，一條一條列出該檔案的所有 Commit 紀錄。點擊其中一條，還能直接開啟對比畫面！
    

你有在 VS Code 裡裝過 GitLens 嗎？還是目前都是用純內建的功能在看 code 呢？
