Spot on—standalone Arkime can run completely on its own, but the **Malcolm Common Fields** panel appears because you are using Malcolm's unified stack.

In a default, standalone setup, Arkime only processes raw PCAP files and displays its own native session fields. However, Malcolm uses Logstash to ingest non-PCAP logs (like Zeek logs and Suricata alerts), normalizes them into a unified schema, and pushes them into OpenSearch. Malcolm then customizes Arkime's UI configuration so that these extra Zeek/Suricata metadata fields—grouped under **Malcolm Common Fields**—render directly inside Arkime's Sessions view.

## How to Interpret This Specific Log

This log record represents an automated security detection generated by Zeek when evaluating TLS/SSL encryption on an internal network connection.

Here is the breakdown of what happened:

### 1. The Connection (Who and Where)

- **Source:** `192.168.65.54` on port `38877`
    
- **Destination:** `192.168.65.67` on port `3389`
    
- **Direction:** `internal` (both IPs belong to internal private subnets)
    
- **Context:** Port `3389` is standard for Remote Desktop Protocol (RDP), which relies on TLS/SSL to negotiate encryption.
    

### 2. The Alert (What Zeek Found)

- **Data Source & Log Type:** `zeek` / `notice`
    
- **Event Category:** `SSL`
    
- **Event Name:** `Invalid_Server_Cert`
    
- **What it means:** When host `.54` initiated an encrypted connection (likely RDP over TLS) to `.67`, host `.67` presented an invalid SSL/TLS certificate. Common reasons for this notice include self-signed certificates, expired certificates, hostname mismatches, or untrusted Root Certificate Authorities (CAs)—extremely common on internal enterprise servers, though sometimes an indicator of a man-in-the-middle attempt.
    

### 3. Risk and Categorization

- **Severity & Risk Score:** `60` (Malcolm assigned a medium-level risk score to this alert).
    
- **Severity Tags:** `Notice (protocol)`
    
- **Tags:** `BEC`, `hhog2424042500000116` (Metadata tags applied during ingestion or PCAP processing).
    

### 4. Correlation & Pivoting

- **Root ID / Log ID:** `C3EgPq1ss6xIN7r5B5`
