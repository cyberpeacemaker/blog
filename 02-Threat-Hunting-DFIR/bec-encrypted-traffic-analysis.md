# BEC Encrypted Traffic Analysis
這是一個非常專業且直擊鑑識核心的問題！

要還原整起事件的完整故事，在本次的調查中，我們確實得益於許多**未加密的明文通訊**。但如果將場景搬到現實世界，面對全加密（HTTPS, SSH, LDAPS）的極端狀況，資安鑑識人員依然有辦法「隔山打牛」推敲出駭客的意圖。

以下我將分成兩部分，先為你解密「這次的其餘故事是怎麼來的」，再聊聊「通訊全加密時，我們如何推敲出駭客的行為」！

## 🔍 故事的其餘拼圖：在本次調查中是如何拼湊的？

在這次的實戰/CTF 中，我們能把故事寫得這麼完整，主要是因為調查了**其他未加密的通訊協定與系統殘留痕跡**：

- **初始入侵（釣魚信）**：我們是透過分析未加密的 **SMTP (電子郵件)** 流量或郵件伺服器日誌，找到了寄件者 `ot@sel.com`。

- **橫向移動與憑證**：

    - **Linux（SSH）**：雖然 SSH 內容是加密的，但連線建立時的握手、協商，以及特定的流量模式（例如：短時間內大量交互的小封包）可以證實 SSH 登入成功。

    - **工程師站（WinRM）**：在許多企業預設環境中，WinRM 預設是走 HTTP (5985 埠口) 的明文傳輸，這讓鑑識人員得以直接捕獲橫向移動的指令。

- **大流量資料外洩**：報告中提到工程師站（`.67`）向檔案伺服器（`.25`）進行了大量檔案傳輸。這是透過分析未加密的 **FTP** 或明文 **HTTP**，並配合 Zeek 的 `files.log` 檔案分析，直接還原並提取出 `Project Info.xml`。

- **工控系統攻擊（OT/ICS）**：變電所使用的 **DNP3 協定預設是完全沒有加密、沒有認證的**。安全監控系統（如 Zeek 或 Suricata 的 DNP3 解析器）可以直接像看小說一樣，看到駭客發送的 `32-Bit Analog Input` 讀取請求與 `Pulse Off` 惡意斷電指令。


## 🛡️ 實戰大哉問：如果通訊全部加密，我們「能」推敲出來嗎？

**答案是：絕對可以！**

即使駭客全程使用 TLS/HTTPS、SSH 加密通道，在不進行 SSL/TLS 解密（Decryption）的情況下，資安人員依然能透過**加密流量分析 (Encrypted Traffic Analytics, ETA)** 與**行為分析 (Behavioral Analysis)** 推敲出以下行為：

### 1. 雖然內容加密，但「連線指紋」會洩漏真實身份 (JA3/JA4)

- **原理**：雖然傳輸的資料被加密了，但在建立連線的 TLS 握手階段（Client Hello），客戶端發送的加密套件（Cipher Suites）順序、支援的 TLS 版本等特徵是**明文**的。

- **推敲方式**：不同的軟體（例如：正常的 Chrome 瀏覽器 vs. 用 Go 語言寫的 Sandcat 木馬）其 TLS 握手特徵截然不同。我們可以用 **JA3/JA4 指紋** 輕鬆識別出：「這個連線雖然假裝自己是 `chrome.exe`，但它的 TLS 指紋其實是一個惡意 Go 程式！」


### 2. 「心跳訊號」的規律性（C2 Beaconing）

- **原理**：木馬程式為了維持與控制總部（C2）的連線，會定期向外「打電話」回報。

- **推敲方式**：這種流量在時間上具有極高的規律性（例如：每 10 秒發送一次 200 位元組的封包，誤差不超過 1 秒）。正常人瀏覽網頁的流量是隨機且有起伏的，而 C2 加密流量在圖表上會呈現一條極其死板的「規律脈搏」，這在行為分析（Anomaly Detection）中一眼就會被抓出來。


### 3. 傳輸特徵與模式（Traffic Profiling）

- **橫向移動**：如果內網兩台平常不怎麼說話的電腦，突然建立起加密連線，且封包特徵呈現「一問一答」的小型突發流量（典型指令輸入輸出），這高度疑似是加密的遠端桌面（RDP）或 SSH 橫向移動。

- **數據外洩**：如果一台電腦平時只傳送幾 KB 的資料，突然在壓縮指令執行後（即便我們不知道壓縮了什麼），立刻向外部某個 IP 連續發送了 50MB 的加密流量，這在行為上就會被直接判定為「加密外洩行為（Encrypted Exfiltration）」。


### 4. 終端行為與網路流量的「時間交叉比對」

- **原理**：網路流量雖然加密，但主機端（端點防護 EDR 或 Windows Sysmon 日誌）會記錄哪一個程式在什麼時間點發起了網路連線。

- **推敲方式**：如果日誌顯示，駭客在主機上執行了 `tar` 或 `Compress-Zipfile`（打包檔案），幾秒鐘後，該主機的網卡立刻出現了往外部未知 IP 的大流量加密傳輸。這兩件事在時間上的高度重合，就算流量加了 2048 位的密，鑑識人員也能百分之百斷定「這是外洩行為」。


在真實世界的資安攻防中，我們很少只單看「網路流量」或只看「主機日誌」，而是將兩者結合，這也就是為什麼現在業界高度依賴 **XDR（跨維度偵測與回應）** 的原因。
