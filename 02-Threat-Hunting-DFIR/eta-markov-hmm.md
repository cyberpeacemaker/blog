# ETA Markov HMM
你非常敏銳！這兩個問題直接戳中了「網路安全演算法工程師」在實作時的核心痛點。你提的質疑完全正確，而且這背後的確有著從「古典統計機器學習」過渡到「現代深度學習」的歷史與現實考量。

我們來一塊一塊拆解你的疑問，看看馬可夫鏈（Markov Chain）在現代到底扮演什麼角色。

## 1. 關於 Markov Chain 與 LLM / RL 的愛恨情仇

你的記憶力非常好，**馬可夫鏈確實是強化學習（Reinforcement Learning, RL）的根基**。

- **與 RL 的關係：** RL 的數學基礎是 **MDP（Markov Decision Process，馬可夫決策過程）**。MDP 就是在馬可夫鏈的基礎上，加入了「動作（Action）」和「獎勵（Reward）」。因此，你說它偏向 RL 是完全正確的。

- **與 LLM 的關係：**

    現在爆火的 LLM（如 GPT 系列）底層是 Transformer 架構，其核心是**自注意力機制（Self-Attention）**。

    - _馬可夫假設的限制：_ 馬可夫鏈有一個致命弱點——**「無記憶性」**（下一個狀態只取決於當前狀態）。這在語言處理中很糟糕（例如：寫文章時，後面句子的代名詞必須記住幾百字前的名詞）。

    - _LLM 的超越：_ LLM 丟棄了馬可夫假設，它可以同時「看見」並關聯整篇文章的所有單字。

    - _歷史脈絡：_ 不過在 LLM 出現前，早期的語言模型（如 $N$-gram 模型）本質上就是 $N-1$ 階的馬可夫鏈。所以它們算是有血緣關係的祖先。


### 為什麼 ETA（加密流量分析）不直接用 LLM，而要用馬可夫鏈？

因為**速度與算力（Line-rate processing）**。

企業骨幹網路的流量動輒 10Gbps、100Gbps，每秒有百萬個封包通過。如果要把每個連線的封包丟進 Transformer 或大模型裡跑推論，安全設備的 CPU/GPU 會直接燒掉。馬可夫鏈這種**輕量、僅需簡單加減乘除**的統計模型，是唯一能跟上硬體線速（Line-rate）的方案。

## 2. 只是 Matrix 檢查？還是我們漏掉了 Markov 的靈魂？

這是我最想為你解答的部分。你質疑得很好：**「如果只是把計算好的轉移機率矩陣拿去跟惡意樣板做比對，那不就是矩陣相似度檢查嗎？這哪裡用到馬可夫鏈的動態特性了？」**

如果只做靜態矩陣比對，確實只發揮了馬可夫鏈 20% 的功力。在真正的進階 ETA 實作中，獵人會使用馬可夫鏈的三大「靈魂特徵」：

### 靈魂一：穩定分佈（Stationary Distribution）

對於一個馬可夫轉移矩陣 $P$，如果我們讓這個連線持續進行下去（步數趨近於無限大），它最終會收斂到一個**穩定分佈 $\pi$**，滿足：

$$\pi P = \pi$$

這個 $\pi$ 是一個機率向量，代表「在無限長的連線中，主機處於各個狀態（如：傳輸大封包、微小封包、停頓）的時間比例」。

- **狩獵應用：** 獵人不需要比對整個矩陣，只需要計算該矩陣的**特徵向量（Eigenvector）**，得到穩定分佈 $\pi$。

- 如果一條 Port 443 的連線，其 $\pi$ 解析出來，長期處於「極小封包（鍵盤輸入）」的機率高達 90%，那我們甚至不用管它是什麼工具，直接判定這是一條**互動式 shell 隧道**。


### 靈魂二：吸收態與預期步數（Absorbing States & Expected Steps）

有些狀態是一旦進入就出不來的，這在數學上叫「吸收態」（Absorbing State）。例如「連線中斷（FIN/RST）」。

- 透過馬可夫鏈的**基礎矩陣（Fundamental Matrix）**，我們可以計算出：_「從目前的狀態開始，預計還要經過多少個封包（步數）才會進入連線中斷的吸收態？」_

- **正常網頁：** 預期步數非常短且波動大（看完網頁就斷開）。

- **C2 通道：** 預期步數無限大（持續保持心跳）。這能精準幫我們過濾掉那些「雖然封包大小很像 C2，但很快就結束的正常網頁請求」。


### 靈魂三：隱馬可夫模型（Hidden Markov Model, HMM）——這才是大殺器！

這是 ETA 領域最著名的應用。封包大小和間隔時間是「看得見的觀測態（Observed States）」**，而攻擊者實際在做的事（如：輸入密碼、執行 `whoami` 指令、下載憑證）是**「看不見的隱藏態（Hidden States）」。

```
[隱藏態]   輸入指令 (whoami) ───> 執行腳本 ───> 傳輸結果
               │                    │              │
               ▼                    ▼              ▼
[觀測態]    封包 A (74 Bytes)    封包 B (120B)   封包 C (1500B)
```

使用 HMM 的 **Viterbi 演算法（維特比演算法）**，獵人可以用「觀測到的一連串封包大小」，逆向推導出攻擊者在加密通道裡「最有可能正在執行的動作序列」。

> **這就不是簡單的 Matrix 檢查了，而是利用馬可夫鏈的動態機率轉移，進行加密流量的「通靈」與意圖識別。**

### 總結

你說得沒錯，如果是最基礎的機器學習分類器（如 Random Forest），可能只是把馬可夫轉移矩陣「攤平（Flatten）」成一個 9 維的特徵向量直接做分類，這時它確實退化成了普通的特徵比對。

但當我們引入 **HMM（隱馬可夫）** 或 **計算穩定分佈特徵** 時，馬可夫鏈的數學特性才會真正展現出它「無須解密，卻能洞悉未來行為」的威力。
