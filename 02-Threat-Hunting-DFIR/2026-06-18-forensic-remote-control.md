這是一個非常核心且內行的問題！在缺乏主機日誌（沒有 Windows 紀錄檔、沒有 Sysmon 監控）的狀況下，這兩個發生在電腦「內部」的動作（建立 WMI 訂閱、清除命令紀錄），竟然會被資安分析師抓得一清二楚，關鍵就在於：**「駭客是透過網路遠端遙控執行這些指令的，而且他們的通訊秘密被破解了。」**

具體的發現過程可以拆解為以下三個步驟：

### 1. 攔截未加密的 C2 遠端控制流量（網路側）

受害電腦（`.69`）在沦陷後，每隔約 20 秒就會向駭客的內部中繼站（`10.99.40.20`）發送 HTTP `POST /beacon` 請求。雖然這是自動化的定期連線，但在網路側的流量分析工具（Arkime / Zeek）眼中，這些連線的「內容（Payload）」全都被完整錄了下來（封包側錄 PCAP）。

### 2. 關鍵突破：解碼 C2 的通訊內容（Payload Decoding）

Caldera 這個紅隊框架的後門程式（sandcat），在傳送控制指令和回傳執行結果時，為了不讓防毒軟體一眼看穿，會將指令進行 **Base64 編碼**，變成一堆看似亂碼的字串（例如 `R2V0LUNoaWxkSXRlbQ==`）。

資安分析師在報告中指出，他們執行了特定的解碼腳本（報告中寫的 `extract_files.py` 與 `decode_cladera_c2.py --live`），將網路封包中那些 HTTP POST 肚子裡的 Base64 字串全部還原成「明文（Plaintext）」。

### 3. 指令劇本（Playbook）露餡

一解碼之後，駭客在背後透過 PowerShell（執行器：`psh`）所敲擊的每一行指令，都如同被裝了側錄器一樣，以純文字的方式直接呈現在分析師眼前：

* **WMI 後門的露餡點**：
分析師在解碼後的指令中，看到了駭客執行了建立 WMI 事件篩選器（`__EventFilter`）的惡意指令，裡面清清楚楚寫著駭客給它取的名字偽裝成：`"SCCM Event Log Filter"`，並且將觸發動作指向執行 `SELDownloadHelper.exe`。
* **清除日誌的露餡點**：
駭客在做完資料打包與外洩後，自以為聰明地在終端機輸入了 `Clear-History;Clear`（清除命令歷史紀錄並清空畫面），試圖在主機上滅證。
**但這正是最諷刺的地方：**「清除歷史紀錄」這道**指令本身**，必須先從駭客的 C2 伺服器透過網路「傳送」給受害電腦去執行。因此，雖然主機上的紀錄被抹除了，但這道「滅證指令」在網路傳輸的途中，就已經被資安設備側錄並被分析師解碼抓包了。

### 總結

這就是資安鑑識上經典的 **「百密一疏」**。駭客雖然成功清除了受害電腦主機上的足跡（防禦迴避），但因為他們所有的動作都是透過網路遠端下達，只要 C2 通訊協定的編碼被資安分析師成功破譯，駭客在鍵盤上打過的每一個字，就會在網路流量中原形畢露。
