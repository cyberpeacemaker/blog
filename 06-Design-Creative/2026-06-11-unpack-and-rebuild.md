As a developer, modifying a file like this can be a bit of a headache because of that "magic trick" architecture we just talked about. If you just open this HTML file and change a line of text in the body, **nothing will change on the screen** because the browser completely overwrites the initial body with the unpacked template string.

Here are the 3 main methods you can use to modify this file, ranging from the quick-and-dirty way to the proper engineering approach.

---

## Method 1: The "Unpack and Rebuild" Approach (Best for major changes)

Since the bundle was generated by a build tool, the cleanest way to modify it is to let a browser do the unpacking for you, capture the result, and save it as a standard HTML/JS file.

1. **Open the file** in your browser's Developer Tools (F12).
2. Go to the **Elements** tab *after* the page has fully loaded and unpacked.
3. Right-click on the `<html>` or `<body>` tag, and select **Copy -> Copy OuterHTML**.
4. Paste that code into a brand new, empty `.html` file.

> [!NOTE]
> **What you get:** You now have a standard, fully readable HTML file where you can modify the text, CSS, and layout directly.
> **The catch:** The external assets (like fonts or scripts) will now be converted into localized `blob:` URLs. If you refresh your new file, those temporary blobs might break. You will need to replace those `blob:` URLs with standard links to CDN hosting (like Google Fonts) to make it stable.

---

## Method 2: The Direct Template Edit (Best for quick text updates)

If you just want to fix a typo, change a title, or update the wording in one of the steps, you can edit the embedded template string directly.

1. Open the original HTML file in a text editor (like VS Code).
2. Scroll all the way to the bottom until you find the `<script type="__bundler/template">` tag.
3. Look at the massive text string inside it. You will see encoded JSON HTML text (with escaped characters like `\u002F` instead of `/`).
4. Use **Find (Ctrl+F)** to locate the text you want to change (e.g., searching for "Raw intel in").
5. Carefully edit the text inside that string and save.

> [!WARNING]
> Be highly careful not to break the quote marks (`"`) or delete any backslashes, or the JSON parser will fail and the page will break.

---

## Method 3: Reverse-Engineering the Asset Bundle (Best if you want to swap images/fonts)

If you need to replace the logo image or change the underlying fonts, you have to modify the binary manifest payload.

1. Find the asset you want to replace in the `<script type="__bundler/manifest">` JSON block. You can identify it by its `"mime": "image/png"` property.
2. Take your new image, compress it into a `.gz` file (using Gzip), and convert that binary file into a **Base64 string**.
3. Replace the old string in the `"data": "..."` field with your new Base64 string.

When Claude (especially a model like **Claude Fable 5** inside a workspace project) creates a webpage using **Claude Design** or **Artifacts**, it defaults to a compiled, compressed standalone bundle precisely so non-technical users can just "double-click to open it" locally without running into CORS errors or broken links.

Since you are comfortable coding, you don't need Claude to keep doing the micro-adjustments. Here are the cleanest approaches to getting the unpacked files:

---

### Approach 1: The "Two-Word" Prompt Reset (Fastest & Native)

You don't need a paragraph of human language to get what you want, which saves your quota. In your current chat or a fresh workspace chat, simply send a tiny, direct command:

> **"Unbundle this into separate files: index.html, style.css, script.js"**

Claude will immediately refactor the code out of that giant script-manifest prison and output it as standard, separate text files. You can then just use the copy buttons or click download on each individual asset tab.

---

### Approach 2: Exporting Directly from Claude Design

If you are using the actual **Claude Design app interface** (as shown in your workspace screenshot), there is a built-in feature designed specifically for this workflow.

* Look at the top-right or bottom actions panel of your active design workspace.
* Instead of downloading the "standalone" copy, Claude Design features an **Export** option.
* Clicking this will download a tidy **ZIP archive** containing your raw materials: a clean `index.html` file with natively linked stylesheets and asset folders. This can be opened in any IDE (like VS Code) for immediate editing.

---

### Approach 3: The Developer "Inspect" Hack (No Tokens Required)

If you don't want to use even *one* more prompt, you can use your browser to force the file to unpack itself for you:

1. Double-click your `MOU Pitch Landing Page (standalone).html` file to open it in Google Chrome or any browser.
2. Press **F12** (or right-click and select **Inspect**) to open the Developer Tools.
3. Once the page is fully rendered, look at the **Elements** tab. Because the browser's JavaScript engine already did the heavy lifting of inflating the compressed data, you are looking at the raw, un-minified DOM structure!
4. Right-click the root `<html>` or `<body>` tag, select **Copy** $\rightarrow$ **Copy outerHTML**, and paste it into your code editor.

*Note on this approach:* The browser will convert embedded assets into local `blob:` strings. You will just need to quickly swap out the font/script blobs with direct CDN links to clean it up.

### Summary

The absolute best developer approach here is **Approach 2** (look for the zip/export button in the Design interface) or using **Approach 1** with a 5-word text prompt. It gives you clean, semantic code blocks that you can run locally and tweak instantly on your own!
